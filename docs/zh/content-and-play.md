# 内容、角色与游玩

[English](../en/content-and-play.md) | 简体中文

本页介绍当前程序的内容与游玩流程。已有安装升级前请先看[应用更新](updates.md)。

## 世界、资料册、规则和冒险分别做什么

| 内容 | 用途 |
|---|---|
| 世界 | 一局游戏的场景与身份，包含背景、默认规则及关联资料册 |
| 资料册 | 按需给 GM 提供人物、地点、物品、势力和背景知识 |
| 规则 | 决定检定、角色和战斗的权威能力；翻译名称不会改变机制 |
| 冒险 | 带版本的剧情图，包含场景、目标、分支和可选遭遇 |
| 内容包 | 可以安装的来源，提供冒险及可复用资源 |

世界的简短介绍是设定摘要，详细知识通常来自资料册。安装内容包不会把整包资料一次性塞入每次模型请求。

在**内容库**浏览世界、冒险和资料册。世界卡片可以开局或管理资料册；世界画廊还提供预览与**克隆世界**，克隆后获得可编辑的个人世界。

资料册卡片保留资料册自己的标题，并单独标明所属世界。用世界名称初始化的主资料册会加上“主资料册”标识，独立资料册另行标注；这些展示不会重命名已保存的数据。

在**世界资料**中，当前资料册列表按当前世界/游戏范围及所选内容语言显示。从内容库直接打开独立资料册时，只补入链接指定的那一本；切换世界或语言到另一世界会清除旧资料册、旧条目的链接目标，不改变正在游玩的存档。

**设置 → 外观 → 系统语言**与右上角的语言选择同步，保存在当前设备。**设置 → 高级 → 生成参数 → DF Agent Token**单独调整 Agent 每次模型请求的最大输出 Token（默认 4096）。Agent 使用主模型，内容生成工具保留各自预算；这不是整项任务的累计 Token 或费用上限。

创建游戏可以选择世界模板、自定义或 AI 生成草稿。整理后的界面保留常用选择，语言、种子、补充背景及本局资料册选择放在展开设置中。勾选本局使用的资料册只改变本局绑定；编辑共享来源资料册可能影响同样引用它的其他游戏，需要独立内容时应先复制。

标准自由对局使用普通 GM 叙事；冒险模式沿所选冒险和支持的规则推进。服务端检查兼容性，不会把 D&D 2014 模组悄悄转换成 D&D 2024。

## 安装或制作冒险

1. 从内容库打开**内容包**，选择在线内容或本地 `.dfplugin` 文件。
2. 预览安装影响，解决阻断项后确认安装，检查完成状态或错误提示。
3. 打开包详情，选择冒险并点击**用此冒险开局**。
4. 检查世界、规则、资料册和角色，再开始游戏。

**冒险包管理**可以新建冒险、AI 生成草稿、导入原生冒险包、导入剧本与外部模组，或整理现有文字。存档绑定冒险身份、版本和摘要；会破坏绑定的更新、禁用和卸载操作会被阻止。先查看受影响存档，不要直接删包文件绕过保护。

## 导入剧本、PDF 或外部模组

导入页支持 UTF-8 Markdown/TXT、Foundry Adventure 导出 JSON、未加密 Fantasy Grounds XML/`.mod`，以及有文字层的 PDF。它把本地数据读成草稿，不执行模组脚本、不安装整个 Foundry 系统、不读取任意 LevelDB 合集、不下载外部附件。扫描 PDF 需要先 OCR。

1. 选择文件并解析，检查章节、场景、GM 备注、资源和引用。
2. 修改草稿和可见范围。导入内容默认仅 GM 可见，需要公开的内容应明确设为公开。
3. 解决错误；未解析的人物、地点和遭遇引用会阻止发布，也可以明确选择仅保留为文字。
4. 编辑后重新校验，查看发布检查项并确认审核；页面会说明**发布为冒险**为何不可用。
5. 发布有效草稿，再用这个冒险创建游戏。

外部正文中的数值保持为参考资料，不会自动把怪物、法术、奖励或房规变成可执行机制。

**AI 整理草稿**是可选项，使用设置中的主模型，把正文发给该服务商并消耗 token；启动前需要确认用量提示。进度条表示已完成的步骤，不保证耗时。取消或关闭导入窗口会中止待处理工作，已完成的调用仍可能计费。先查看生成结果，明确采用后才替换当前草稿；失败、取消和未采用的结果不会覆盖编辑内容。采用后仍需重新校验和确认发布。

## 冒险分支与秘密

GM 查看完整冒险，玩家只收到公开投影。原生排他选择可以收集玩家提议，由 GM 确认后提交一条分支；服务端校验当前局次和状态，过期提议不能推进另一局。

文字标记 `@choice 描述 -> 场景ID` 定义剧情连接，多条无条件连接可能同时开放；单靠这个标记不声明原生排他选择组。需要互斥分支时，在冒险编辑器配置结构化选择。

## 角色卡、邀请与 AI 席位

**角色卡库**保存可复用卡片，**本局角色**管理当前游戏里的参与者。已行动角色采用卡片需要 GM 权限。角色模板和角色在一局中的实际状态用途不同。

在游玩页队伍成员列表下点击**邀请玩家**，分享真正的邀请链接，玩家直接打开即可；不需要从链接提取并手输 `web|房间|房主`。邀请和席位凭据遵守服务端访问策略，旧链接中的裸玩家 ID 不再算凭据；旧链接无法认证时，请 GM 重新邀请。

AI 托管角色与同伴沿用人类玩家的服务端行动和规则边界，其策略随存档保存；叙事不能自行赋予私密信息，也不能绕过资源扣减。

## 检定与战斗

可用检定模式取决于规则和 GM 策略。CoC 孤注一掷绑定符合条件的失败检定，不是任意重掷；需要的 GM 同意和后果始终关联该检定。

D&D 2024 权威战斗中的可用法术取决于已准备或职业授予的法术、资源和当前触发条件。2 级以上圣武士通过职业特性获得**至圣斩**；符合条件的近战命中后，仍有附赠动作及法术位或免费次数时才出现。它不是始终可用的普通攻击按钮，长休恢复职业免费次数。这遵循当前支持的 2024 规则，不是 2014 至圣斩。

轻量规则和自定义规则只提供运行时明确声明的动作，不会从职业名称猜测法术机制。具体边界见[规则与骰子](rules-and-dice.md)和[自动化覆盖清单](../rulesets/dnd2024/AUTOMATION_COVERAGE.md)。

## DF Agent 与恢复

房主的 DF Agent 可以查文档、读取游戏和内容状态、准备草稿。模型请求写操作时，必须经过应用里的审核确认，且继续受对应服务权限限制；普通玩家页面没有房主 Agent。确认前查看拟议改动，AI 操作使用配置的服务商，可能消耗 token。

执行操作以实际工具目录和当前应用状态为准。需要使用说明时才调用 `search_documentation`，检索本版本自带的英语或简体中文说明；开发目录使用当前本地文件。远程持续变化的手册和旧的无版本索引不决定 Agent 能做什么，也不再自动塞入每次对话。

手机游玩页的**游戏工具**汇集角色信息、场景地图和队伍，GM 工作台保留顶部独立入口；紧凑角色状态条也可打开角色抽屉。原来重复的悬浮导航按钮已移除。

资料册操作历史支持检查和恢复相应改动，记录仅房主可见，恢复计划也会经过校验。它不能替代版本升级备份：改程序版本前请保留完整 `data/`。
